Software engineering case study

Keeping hard gates hard

Verification infrastructure for an evidence-first job-search engine: deterministic résumé extraction checks, executable scoring contracts, and an adversarial test for the bug that looks reasonable until it costs a candidate time.

01 / Problem

Confidence can be structurally wrong

An early-career international candidate on an OPT timeline cannot afford to spend a day on an application that should have been rejected in seconds. Two hidden failures distort that allocation decision.

A résumé PDF can look polished while its extracted text drops a heading, separates a date from its role, or scrambles section order. At the same time, a scoring engine can treat job-posting liveness or visa timing as ordinary weighted preferences. That lets strong secondary signals rescue a role that should have been vetoed.

The repository described both contracts. It did not yet have an automated control that passed on production behavior and failed on the exact gate-as-vote bug the project names.

02 / Build

One system, three verification layers

I developed a unified contribution that turns both risks into executable contracts. The implementation separates extraction mechanics, scoring behavior, and evidence provenance so each layer can fail closed without claiming the human decision.

  1. ATS parse layer

    Render public Markdown to a temporary PDF, extract with PDF.js, and verify source-backed names, titles, dates, headings, and reading order.

  2. Gate contract layer

    Run a six-case truth table through the production scorer, then inject a deliberate mutation that changes hard multipliers into weighted votes.

  3. Evidence layer

    Reconcile counts, trace numeric output to scripts and records, block private paths, and retain HUMAN_REVIEW_REQUIRED.

04 / Boundary

Verified is smaller than plausible

Controlled gate values are labeled local evidence. Parser identity is an external dependency record. Counts and verdicts are script output. Real-world facts the harness cannot observe remain missing.

The machine verifies

  • PDF.js produced a nonempty text layer.
  • Declared fields are present and ordered.
  • Production arithmetic matches the truth table.
  • Zero gates force composite zero and Skip.
  • The named mutation fails.
  • Public counts reconcile to JSON records.

The machine does not know

  • Whether a commercial ATS parses identically.
  • Whether résumé claims are true or persuasive.
  • Whether visual design is professionally effective.
  • Whether a live posting or visa timeline is current.
  • Whether scorer weights are calibrated.
  • Whether the candidate should apply.

05 / Failure modes

Failure paths are part of the interface

  • Gate-as-vote regressionA zero gate returns a nonzero composite or a non-Skip decision. The suite blocks handoff.
  • Expectation driftA declared field no longer matches its source line. Verification stops with a contract error.
  • Missing or scrambled extractionThe audit names each absent or reordered field and exits nonzero.
  • Private-data escapePublic output from a real résumé is rejected; staged and tracked paths are scanned.
  • Parser pass mistaken for qualityMechanical success retains a human review requirement for content and visual adequacy.
  • Recipe/card driftThe AI procedure and human operating card share one version and must change together.

A PDF.js pass is not proof that Workday, iCIMS, or another commercial ATS will parse identically. A correct gate formula is only as truthful as the liveness and timeline records supplied to it.
