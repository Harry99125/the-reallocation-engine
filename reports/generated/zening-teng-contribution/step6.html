Software engineering case study

Two safety checks for a job-search tool

I built a résumé PDF checker and a database-backed test that keeps two important scoring gates from turning into normal scores.

Zening Teng · Node.js · PDF.js · Playwright · Automated testing

2 / 2

01 / Problem

A result can look right and still be wrong

An international student has limited time to apply for jobs. A bad system can waste that time in two ways.

A résumé can look correct on screen while its PDF text is missing a heading, date, or job title. The scorer can also treat job liveness or visa timing like normal scores. That mistake can turn a job that should be skipped into an Apply.

The project explained both rules, but it did not have automated tests for both of them.

02 / Build

What I built

I kept the work in three small parts. Each part has one clear job.

  1. Résumé checker

    Turn public Markdown into a temporary PDF, extract its text with PDF.js, and check names, titles, dates, headings, and order.

  2. Gate checker

    Read and check a stored H-1B record, run three Chapter gate cases through the real scorer, then run a wrong version that adds hard gates like scores.

  3. Evidence checker

    Check the totals, show where the numbers came from, block private files, and keep the final decision with a person.

The real résumé run stayed private. After Zening Teng approved recipe 0.12.0 and the current database hash, I reran the database-backed gate harness and both public ATS cases. Step 4 records that post-approval run.

04 / Boundary

What the programs know

The programs check code and saved files. They do not know whether the real world matches those inputs.

The programs check

  • PDF.js produced a nonempty text layer.
  • Declared fields are present and ordered.
  • The stored H-1B rate matches approvals and denials.
  • The real scorer matches the database-backed gate cases.
  • A zero gate produces zero and Skip.
  • The known bad version fails.
  • The totals match the JSON records.

The programs do not know

  • Whether every commercial ATS reads the same PDF.
  • Whether résumé claims are true or convincing.
  • Whether the résumé design looks professional.
  • Whether a real job or visa timeline is current.
  • Whether the mapped company join is correct.
  • The full sponsorship probability.
  • Whether the scoring weights are good.
  • Whether a person should apply.

05 / Failure modes

Problems I tested

  • Gate becomes a scoreA zero gate returns a nonzero result or something other than Skip. The test fails.
  • Expected data changesAn expected field no longer matches its public source line. The program stops.
  • Missing or mixed-up textThe report names every missing or reordered field and returns a failure.
  • Private data leaksReal résumé output cannot be written into the public report folders.
  • A parser pass sounds like a quality scoreThe report still tells a person to review the content and design.
  • Instructions stop matchingThe AI recipe and human card share one version and must change together.
  • Database evidence driftsA changed file hash or approval-rate mismatch stops the evidence check.

A PDF.js pass does not prove that Workday, iCIMS, or another ATS will read the résumé the same way. A correct formula also cannot verify the stored company join, create the missing sponsorship inputs, or fix bad job and visa data. Missing results stay NOT IMPLEMENTED.
